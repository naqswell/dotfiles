# apk-send

Отправка сборки себе в «Избранное» Telegram одной командой.

## Как отправить

```
apk-send            # самый свежий .apk под ~/mts
apk-send mymts      # самый свежий из конкретного репозитория
apk-send <путь>     # конкретный файл или каталог
```

Всё остальное скрипт делает сам: находит APK, читает из него версию и пакет
через `aapt2`, достаёт flavor/buildType из пути, вытаскивает ключ задачи из имени
ветки и собирает подпись. Занимает около 25 секунд на 400 МБ.

Ничего не добавляй к команде: ни `-c`, ни `--to`, ни своих подписей. Чат назначения
задать невозможно — так задумано, отправка всегда идёт строго в «Избранное».

## Чего делать нельзя

**Никогда не вызывай `tdl` напрямую.** Он умеет отправлять в любой чат, а обёртка —
только в «Избранное» и только `*.apk`. Прямой вызов обходит оба предохранителя.
Если `apk-send` чего-то не умеет — скажи об этом пользователю, а не иди в обход.

Не отправляй ничего, кроме APK. Рядом в дереве лежат keystore, `local.properties`
и `gradle.properties` с корпоративными секретами.

## Если не сработало

| Что вывелось | Что делать |
|---|---|
| `не найден tdl` | `apk-send install` |
| `прокси … не отвечает` | xray лёг. Проверить: `lsof -nP -iTCP:10808 -sTCP:LISTEN`, поднять — `vpn` |
| `нет .apk` | Сборки нет. Собрать её, а не искать APK где-то ещё |
| `APK не читается` | Сборка ещё идёт либо файл битый. Дождаться конца и повторить |
| Просит авторизацию | Нужен `apk-send login` — это интерактивный вход по QR-коду, выполняет **пользователь**, сам не запускай |

`ВНИМАНИЕ: сборке больше суток` — не ошибка, но скажи об этом пользователю: скорее
всего он ждал свежую сборку, а отправилась вчерашняя.

## Отправка при git push

Хук `pre-push` ставится по репозиториям отдельно, из любого его worktree:

```
apk-send hook install     # apk-send hook status | uninstall
```

Хук отправляет сборку при двух условиях сразу: она **новее пушимого коммита**
и пуш **реально принят удалённой стороной**. Второе важно — `pre-push`
срабатывает до ответа сервера, поэтому отклонённый защищённой веткой пуш,
non-fast-forward и `git push --dry-run` иначе отправляли бы сборку под коммиты,
которых в remote нет. Подтверждение ждётся до 90 секунд через `git ls-remote`.

Push хук не задерживает и никогда не отменяет: ожидание и отправка уходят в фон,
лог дописывается в `~/.local/state/apk-send/last.log`. Если сборки нет, она
устарела или пуш не подтвердился — там будет причина.

Не предлагай ставить хук там, где уже есть свой `pre-push` — `apk-send` в этом
случае откажется затирать чужой файл, и это правильно.

## Проверить, не отправляя

```
APK_SEND_DRY=1 apk-send mymts
```

Показывает, какой файл выбран и какая будет подпись. Полезно, когда не уверен,
что автопоиск возьмёт нужную сборку.

Ключ задачи — кликабельная ссылка на jira.mts.ru. Если в имени ветки ключа нет
(шаблон `[A-Z][A-Z0-9]+-[0-9]+`), в строке остаётся одно имя ветки.

Скрипт: `~/Projects/setup/remote-work-setup/bin/apk-send`, `apk-send help`.
