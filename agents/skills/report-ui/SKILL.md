# report-ui

Отвечает на два вопроса: что я задел визуально и не задел ли лишнего.
Читатель — ты сам, поэтому технические подробности здесь уместны.

Уходит в «Избранное» Telegram сразу, без показа черновика.

## Собери факты

Диапазон — от базы до текущего состояния. Единственный источник фактов git:

```
base=$(git merge-base HEAD origin/develop)
git log --oneline "$base"..HEAD
git status --porcelain
```

Незакоммиченное в отчёт входит, но отдельной строкой «не закоммичено — в сборке
может отсутствовать». `@{upstream}` не используй: у части воркри platsdk
апстрима нет, у одного он смотрит на чужую ветку.

## Сними кадры

```
cache=$(platsdk-baseline "$base" | tail -1)
./gradlew :presentation:ui:testDebugUnitTest --tests 'ru.mts.platsdk.ui.screenshot.*'
gallery-diff "$cache" presentation/ui/build/screenshots
```

`gallery-diff` печатает JSON: `changed` и `common` — сколько кадров разошлось из
скольких, `screens` — разбивка по экранам, `findings` — дельта автопроверок,
`representative` — по одному кадру на затронутый экран с путями `before` и
`after`.

Матрица упала или проект не собрался — отчёт всё равно отправь, текстом, со
строкой «скриншоты снять не удалось» и причиной. Ты рядом, разберёшься.

Репозиторий без скриншот-матрицы (всё, кроме platsdk) — отчёт уходит текстом со
строкой «скриншотов нет: в репозитории не найдена матрица». Молчать про
скриншоты нельзя: отчёт без раздела читается как «UI не менялся».

## Отправь

Сначала пары кадров, по одной паре на затронутый экран, из `representative`:

```
apk-send file <before> "ДО · <screenTitle> · <caseTitle>
<id>"
apk-send file <after>  "ПОСЛЕ · <screenTitle> · <caseTitle>
<id>"
```

`id` вида `c2c/dataLongAmount@narrow/fs2.0/dark` — это адрес кадра в галерее,
по нему кадр находится поиском. Человеческий заголовок отвечает на «что это»,
`id` — на «где это». Нужны оба.

Потом сам отчёт файлом:

```
apk-send file отчёт.md "UI · <репозиторий> · <ветка>
<N> кадров из <M> · экранов затронуто <K>"
```

## Что в отчёте

- Сводка: сколько кадров разошлось из скольких общих, разбивка по экранам.
- Дельта находок: появилось N, исчезло M, с адресами кадров. Новая находка —
  это готовый дефект, автопроверка ловит срезанный текст и невидимый элемент.
- Кадры, которых нет в базе или которых не стало, если такие есть.
- Экраны, тронутые в коде, но не покрытые матрицей. Вовсе нет кадров у
  OtpScreen, WebViewScreen, старого ResultScreen и трёх экранов BNPL — их
  список ведёт `MatrixCoverageTest.excused`. Отдельно отмечай, что состояние
  могло не попасть в матрицу: отбор состояний одноразовый, полного перебора нет.
- Незакоммиченное, отдельным блоком.

Ноль расхождений — не повод молчать. Отчёт уходит со строкой «визуальных
изменений нет» и списком того, что было тронуто в коде: ты правил интерфейс и
хотел увидеть результат, «ничего не изменилось» это ответ, иногда тревожный.

## Чего не делай

Не пиши «этот экран изменился из-за вот этого composable». Автоматической связи
«изменённый файл → кадр» в platsdk нет, такая строка будет догадкой с
интонацией факта.

Не тащи в отчёт список изменённых файлов. Дифф ты и так видишь.
