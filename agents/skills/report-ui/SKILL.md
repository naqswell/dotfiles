# report-ui

Отвечает на два вопроса: что я задел визуально и не задел ли лишнего.
Читатель — ты сам, поэтому технические подробности здесь уместны.

Уходит в «Избранное» Telegram сразу, без показа черновика.

## Собери факты

Диапазон — от базы до текущего состояния. Единственный источник фактов git:

```
base=$(git merge-base HEAD origin/develop)
git log --oneline "$base"..HEAD
git status --porcelain
```

Незакоммиченное в отчёт входит, но отдельной строкой «не закоммичено — в сборке
может отсутствовать». `@{upstream}` не используй: у части воркри platsdk
апстрима нет, у одного он смотрит на чужую ветку.

## Сними кадры

```
cache=$(platsdk-baseline "$base")
./gradlew :presentation:ui:testDebugUnitTest --tests 'ru.mts.platsdk.ui.screenshot.*' \
  && gallery-diff "$cache" presentation/ui/build/screenshots
```

`gallery-diff` печатает JSON: `changed` и `common` — сколько кадров разошлось из
скольких, `added` и `removed` — сколько появилось и пропало, `screens` — разбивка
по экранам, `findings` — дельта автопроверок, `representative` — по одному кадру
на затронутый экран с путями `before` и `after` и признаками `isNew`,
`beforeMissing`.

Экран, у которого `changed: 0`, а `added` больше нуля, — новый: в базе его кадров
не было. Пропустить его нельзя, это и есть самое заметное изменение.

Матрица упала или проект не собрался — отчёт всё равно отправь, текстом, со
строкой «скриншоты снять не удалось» и причиной. Ты рядом, разберёшься.

Репозиторий без скриншот-матрицы (всё, кроме platsdk) — отчёт уходит текстом со
строкой «скриншотов нет: в репозитории не найдена матрица». Молчать про
скриншоты нельзя: отчёт без раздела читается как «UI не менялся».

## Отправь

Сначала пары кадров, по одной паре на затронутый экран, из `representative`:

```
apk-send file <before> "ДО · <screenTitle> · <caseTitle>
<id>"
apk-send file <after>  "ПОСЛЕ · <screenTitle> · <caseTitle>
<id>"
```

`id` вида `c2c/dataLongAmount@narrow/fs2.0/dark` — это адрес кадра в галерее,
по нему кадр находится поиском. Человеческий заголовок отвечает на «что это»,
`id` — на «где это». Нужны оба.

Пара выходит не всегда, и путать два случая нельзя:

- `isNew: true` — кадра в базе не было вовсе, экран или состояние новые. Шли один
  кадр с подписью «НОВЫЙ», а не «ПОСЛЕ»: сравнивать не с чем и не должно быть.
- `beforeMissing: true` — кадр не новый, но его «до» в кэше базы нет. Так бывает,
  когда изменения легли вне опорного устройства. Шли «ПОСЛЕ» и **прямо скажи в
  отчёте**, что «до» снять не удалось. Молча отправить один кадр значит выдать его
  за новый.

Потом сам отчёт файлом:

```
apk-send file ui-<репозиторий>-<ветка>-<ДД.ММ>.md "UI · <репозиторий> · <ветка>
<N> кадров из <M> · экранов затронуто <K>"
```
Имя файла обязано нести линзу, репозиторий и ветку: в «Избранном» отчёты со всех
веток лежат вперемешку, и три `отчёт.md` подряд неразличимы. Формат —
`<линза>-<репозиторий>-<ветка без feature/|bugfix/>-<ДД.ММ>.md`, например
`ui-platsdk-fatal-modal-10.09.md`. Косые черты в имени ветки заменяй дефисом.


## Текст отчёта подчиняется `unslop`

`unslop` объявлен как «Must always apply» и в сессии обычно уже действует — тогда
пиши сразу по его правилам. Не загружен — загрузи скилл один раз.

**Второго прохода не делай.** Уже написанный по правилам текст не надо потом ещё
раз «прогонять»: `unslop` сам предупреждает, что вылизанный до стерильности текст
заметен ровно так же, как канцелярит.

Это не про красоту. Канцелярит съедает внимание, а ты читаешь этот отчёт между
делом, чтобы понять, задел ли лишнее.

Подписи к файлам — тот же текст и те же правила.

## Что в отчёте

- Сводка: сколько кадров разошлось из скольких общих, разбивка по экранам.
- Дельта находок: появилось N, исчезло M, с адресами кадров. Новая находка —
  это готовый дефект, автопроверка ловит срезанный текст и невидимый элемент.
- Кадры, которых нет в базе или которых не стало, если такие есть.
- Экраны, тронутые в коде, но не покрытые матрицей. Список непокрытых ведёт
  `MatrixCoverageTest.excused` — не помни его наизусть, вычитай:

```
test=presentation/ui/src/test/java/ru/mts/platsdk/ui/screenshot/MatrixCoverageTest.kt
[ -f "$test" ] || echo "МАТРИЦЫ В ЭТОМ РЕПОЗИТОРИИ НЕТ"
sed -n '/val excused/,/^    )/p' "$test" 2>/dev/null | grep -oE '[A-Za-z0-9]+Screen::class' | sed 's/::class//'
git diff --name-only "$base" -- 'presentation/ui/src/main/*' 'presentation/ui-model/src/main/*'
```

Первая команда даёт список непокрытых экранов, вторая — изменённые файлы
интерфейса. **Сопоставь их сам**, автоматического способа нет: имя экрана из
списка встречается в `PlatSdkScreen.kt`, а вёрстка того же экрана живёт в файлах
с другими именами, так что ни грепом по диффу, ни грепом по путям это не решается.

Три правила, чтобы не соврать:

- вывод пуст или напечатано `МАТРИЦЫ В ЭТОМ РЕПОЗИТОРИИ НЕТ` — раздел пропусти и
  скажи об этом прямо. Молча написать «непокрытых экранов не тронуто» нельзя: это
  утверждение, для которого у тебя нет данных;
- диапазон здесь `"$base"` без `..HEAD`, чтобы в дифф попало и незакоммиченное;
- в чём не уверен, помечай как неуверенное. «Возможно, затронут» — честный ответ,
  «не затронут» без проверки — нет.

  Отдельно отмечай, что состояние могло не попасть в матрицу: отбор состояний
  одноразовый, полного перебора нет.
- Незакоммиченное, отдельным блоком.

Ноль расхождений — не повод молчать. Отчёт уходит со строкой «визуальных
изменений нет» и списком того, что было тронуто в коде: ты правил интерфейс и
хотел увидеть результат, «ничего не изменилось» это ответ, иногда тревожный.

## Чего не делай

Не пиши «этот экран изменился из-за вот этого composable». Автоматической связи
«изменённый файл → кадр» в platsdk нет, такая строка будет догадкой с
интонацией факта.

Не тащи в отчёт список изменённых файлов. Дифф ты и так видишь.
