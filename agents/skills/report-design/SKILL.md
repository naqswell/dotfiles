# report-design

Показывает, какие экраны затронуты и как они теперь выглядят.

Отчёт приходит в твоё «Избранное». Пересылаешь его ты. «Для дизайнера» — про
язык и подбор кадров, не про адресата.

Уходит сразу, без показа черновика.

## Сними расхождения

```
base=$(git merge-base HEAD origin/develop)
cache=$(platsdk-baseline "$base")
zip="/tmp/srez-<ветка>-<ДД.ММ>.zip"
./gradlew :presentation:ui:testDebugUnitTest --tests 'ru.mts.platsdk.ui.screenshot.*' \
  && gallery-diff "$cache" presentation/ui/build/screenshots --zip "$zip"
```

В JSON смотри `changed` (кадры разошлись), `added` (кадров не было в базе) и
`screens`. Экран с `changed: 0` и ненулевым `added` — новый, и это самое заметное
изменение, а не повод его пропустить.

Путь к архиву бери из поля `zip` выходного JSON, а не из своей переменной
`$zip`: при нуле расхождений поля не будет, и отправлять нечего. Переменная же
останется заполненной в любом случае, включая падение матрицы.
Поля нет — архива нет, и слать по этому пути нечего.

Матрица не собралась — **ничего не отправляй**, скажи причину в терминале. Весь
смысл этого отчёта в картинках, текстовый огрызок «не удалось снять» дизайнеру
не сообщение, а мусор в канале.

`gallery-diff` предупредил, что галерея этого воркри не умеет частичный набор, —
скажи об этом пользователю. Срез откроется пустой страницей, если в него не попал
опорный кадр; лечится вливанием правки галереи в develop.

Ноль расхождений и ноль новых кадров — ничего не отправляй, скажи в терминале.
«Изменений нет» приучает игнорировать канал.

## Отправь кадры

По одному кадру «после» на затронутый экран, из `representative`:

```
apk-send file <after> "<screenTitle> · <caseTitle>
<deviceTitle>, шрифт <fontScale>, <themeTitle>
<id>"
```

Подпись работает в два слоя. Заголовки отвечают на «что это»: «Перевод по
номеру карты · длинная сумма · узкий экран · шрифт 2.0 · тёмная тема». Строка
`id` вида `c2c/dataLongAmount@narrow/fs2.0/dark` — точный адрес кадра: по нему
кадр находится в галерее, и под каждым кадром там стоит кнопка «копировать»
ровно для этой строки. Давать только заголовок значит лишить человека
возможности найти кадр; только `id` — заставить расшифровывать `fs2.0/dark`.

Кадр с `isNew: true` — это новый экран или новое состояние: так и подписывай,
«новый экран», а не «изменился». Дизайнеру разница важнее всего: в первом случае
макет надо посмотреть впервые, во втором — сравнить с тем, что было.

Потолок считай в экранах, а не в кадрах. Экранов в матрице десять, взрыва не
будет; кадров могут быть сотни.

## Отправь срез и отчёт

```
apk-send file <путь из поля zip> "Галерея изменений · <ветка>
<K> экранов, <N> кадров"
apk-send file design-<репозиторий>-<ветка>-<ДД.ММ>.md "Дизайн · platsdk · <ветка>
<две-три строки сути>"
```
Имя файла обязано нести линзу, репозиторий и ветку: в «Избранном» отчёты со всех
веток лежат вперемешку, и три `отчёт.md` подряд неразличимы. Формат —
`<линза>-<репозиторий>-<ветка без feature/|bugfix/>-<ДД.ММ>.md`, например
`design-platsdk-fatal-modal-10.09.md`. Косые черты в имени ветки заменяй дефисом.


Срез открывается двойным щелчком по `index.html` внутри архива и содержит
только изменившиеся кадры, с фильтрами по экрану, устройству, шрифту и теме.

## Перед отправкой прогони текст через `unslop`

Вызови скилл `unslop` и примени его правки к тексту отчёта до того, как
отправлять. Всё, что ты пишешь здесь, читает человек — и читает по диагонали.

Это не про красоту. Канцелярит и дежурные обороты съедают внимание, а внимания
у читателя ровно столько, чтобы дойти до пункта «что проверить». Отчёт, который
лень читать, читают невнимательно.

Подписи к файлам тоже текст: их через `unslop` тоже.

## Что в отчёте

- Затронутые экраны списком: заголовок и `id` опорного кадра у каждого.
- Что изменилось визуально, словами. Экранами и элементами, без имён классов,
  файлов и модулей.
- Дельта находок автопроверки: «на узком экране при шрифте 2.0 текст
  перестал помещаться» с адресом кадра. Автопроверка ловит два случая: текст
  срезан в своём боксе и значимый элемент не виден, до него нельзя доскроллить.
- Отдельным блоком — **чего на картинках не увидеть**: экраны, тронутые в коде,
  но не покрытые матрицей вовсе, и состояния, которые могли в матрицу не попасть
  (отбор одноразовый, полного перебора нет).

  Список непокрытых экранов вычитай из теста, наизусть не помни:

```
test=presentation/ui/src/test/java/ru/mts/platsdk/ui/screenshot/MatrixCoverageTest.kt
[ -f "$test" ] || echo "МАТРИЦЫ В ЭТОМ РЕПОЗИТОРИИ НЕТ"
sed -n '/val excused/,/^    )/p' "$test" 2>/dev/null | grep -oE '[A-Za-z0-9]+Screen::class' | sed 's/::class//'
git diff --name-only "$base" -- 'presentation/ui/src/main/*' 'presentation/ui-model/src/main/*'
```

Первая команда даёт список непокрытых экранов, вторая — изменённые файлы
интерфейса. **Сопоставь их сам**, автоматического способа нет: имя экрана из
списка встречается в `PlatSdkScreen.kt`, а вёрстка того же экрана живёт в файлах
с другими именами, так что ни грепом по диффу, ни грепом по путям это не решается.

Три правила, чтобы не соврать:

- вывод пуст или напечатано `МАТРИЦЫ В ЭТОМ РЕПОЗИТОРИИ НЕТ` — раздел пропусти и
  скажи об этом прямо. Молча написать «непокрытых экранов не тронуто» нельзя: это
  утверждение, для которого у тебя нет данных;
- диапазон здесь `"$base"` без `..HEAD`, чтобы в дифф попало и незакоммиченное;
- в чём не уверен, помечай как неуверенное. «Возможно, затронут» — честный ответ,
  «не затронут» без проверки — нет.

  Это самый ценный раздел для дизайнера: «поменяли, но никто не увидел».

## Чего не делай

Не отправляй полную галерею вместо среза. 2840 кадров на 244 МиБ вместо ответа
«что поменялось» — это перекладывание работы на получателя.

Не объясняй изменения через код. «Поправили `C2cPane`» дизайнеру не говорит
ничего, а связи «файл → кадр» в проекте всё равно нет, так что и звучало бы это
как факт, не будучи им.
