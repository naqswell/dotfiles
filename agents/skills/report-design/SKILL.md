# report-design

Показывает, какие экраны затронуты и как они теперь выглядят.

Отчёт приходит в твоё «Избранное». Пересылаешь его ты. «Для дизайнера» — про
язык и подбор кадров, не про адресата.

Уходит сразу, без показа черновика.

## Сними расхождения

```
base=$(git merge-base HEAD origin/develop)
cache=$(platsdk-baseline "$base" | tail -1)
./gradlew :presentation:ui:testDebugUnitTest --tests 'ru.mts.platsdk.ui.screenshot.*'
gallery-diff "$cache" presentation/ui/build/screenshots --zip /tmp/srez.zip
```

Матрица не собралась — **ничего не отправляй**, скажи причину в терминале. Весь
смысл этого отчёта в картинках, текстовый огрызок «не удалось снять» дизайнеру
не сообщение, а мусор в канале.

Ноль расхождений — тоже ничего не отправляй, скажи в терминале. «Изменений нет»
приучает игнорировать канал.

## Отправь кадры

По одному кадру «после» на затронутый экран, из `representative`:

```
apk-send file <after> "<screenTitle> · <caseTitle>
<deviceTitle>, шрифт <fontScale>, <themeTitle>
<id>"
```

Подпись работает в два слоя. Заголовки отвечают на «что это»: «Перевод по
номеру карты · длинная сумма · узкий экран · шрифт 2.0 · тёмная тема». Строка
`id` вида `c2c/dataLongAmount@narrow/fs2.0/dark` — точный адрес кадра: по нему
кадр находится в галерее, и под каждым кадром там стоит кнопка «копировать»
ровно для этой строки. Давать только заголовок значит лишить человека
возможности найти кадр; только `id` — заставить расшифровывать `fs2.0/dark`.

Потолок считай в экранах, а не в кадрах. Экранов в матрице десять, взрыва не
будет; кадров могут быть сотни.

## Отправь срез и отчёт

```
apk-send file /tmp/srez.zip "Галерея изменений · <ветка>
<K> экранов, <N> кадров"
apk-send file отчёт.md "Дизайн · platsdk · <ветка>
<две-три строки сути>"
```

Срез открывается двойным щелчком по `index.html` внутри архива и содержит
только изменившиеся кадры, с фильтрами по экрану, устройству, шрифту и теме.

## Что в отчёте

- Затронутые экраны списком: заголовок и `id` опорного кадра у каждого.
- Что изменилось визуально, словами. Экранами и элементами, без имён классов,
  файлов и модулей.
- Дельта находок автопроверки: «на узком экране при шрифте 2.0 текст
  перестал помещаться» с адресом кадра. Автопроверка ловит два случая: текст
  срезан в своём боксе и значимый элемент не виден, до него нельзя доскроллить.
- Отдельным блоком — **чего на картинках не увидеть**:
  - экраны, тронутые в коде, но не покрытые матрицей вовсе. Кадров нет у
    OtpScreen, WebViewScreen, старого ResultScreen и трёх экранов BNPL;
  - состояния, которые могли не попасть в матрицу: отбор одноразовый, полный
    перебор состояний не делается.

  Это самый ценный раздел для дизайнера: «поменяли, но никто не увидел».

## Чего не делай

Не отправляй полную галерею вместо среза. 2840 кадров на 244 МиБ вместо ответа
«что поменялось» — это перекладывание работы на получателя.

Не объясняй изменения через код. «Поправили `C2cPane`» дизайнеру не говорит
ничего, а связи «файл → кадр» в проекте всё равно нет, так что и звучало бы это
как факт, не будучи им.
