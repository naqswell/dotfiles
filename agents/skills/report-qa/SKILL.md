# report-qa

Сборка и текст к ней для человека, который будет щёлкать по приложению руками.

Отчёт приходит в твоё «Избранное», а не тестировщику. Пересылаешь его ты. Слово
«для тестировщика» здесь про язык и содержание, не про адресата.

Уходит сразу, без показа черновика.

## Правило языка

Тестировщик не читает код и не имеет к нему доступа. В отчёте не должно быть
имён файлов, классов, функций, пакетов, модулей, номеров коммитов и веток в
роли объяснения. Всё это он проверить не может, а искать будет.

Пиши экранами и действиями: «на экране перевода по номеру карты», «при вводе
суммы больше остатка», «после возврата из сканера QR».

## Собери факты

Единственный источник фактов git. Ни один пункт «что проверять» не должен
появиться из памяти сессии: за сессию бывает три подхода к задаче, два из
которых откачены, и в сборке их нет.

```
base=$(git merge-base HEAD origin/develop)
git log "$base"..HEAD
git diff --stat "$base"..HEAD
git status --porcelain
```

В platsdk тела коммитов подробные и на русском — это лучший исходник для
формулировок. Ключ задачи там почти всегда в имени ветки, а не в коммите; в
mymts наоборот, префиксом `[KEY]` в сообщении.

Есть ключ задачи и поднят MTS VPN — вытащи из Jira summary и описание через
`mcp__atlassian__jira_get_issue`. Не поднят или ключа нет — отчёт собирается и
без этого, спрашивать не надо.

## Приложи сборку

```
apk-send
```

Сам проект не собирай: сборка занимает минуты и может упасть, отчёт не должен
быть её заложником. APK не нашёлся — отправь отчёт без него и скажи об этом
строкой.

Коммита, из которого собран APK, не знает никто: `apk-send` берёт файл с диска и
печатает только время сборки. Сверь его с последним коммитом диапазона:

```
apk=$(find . -name '*.apk' -path '*/outputs/apk/*' | head -1)
[ "$(stat -f '%m' "$apk")" -lt "$(git log -1 --format=%ct HEAD)" ] \
  && echo "СБОРКА СТАРШЕ ПОСЛЕДНЕГО КОММИТА"
```

Напечаталось — скажи в отчёте прямой строкой, что часть описанного в этой сборке
отсутствует, и назови, какие коммиты в неё не попали. Тестировщик иначе будет
искать то, чего в приложении нет. `apk-send` вдобавок сам предупреждает, если
сборке больше суток, но это про другое: сборка может быть свежей по календарю и
всё равно отставать от кода.

## Приложи срез галереи — или не прикладывай

Срез стоит прогона матрицы: две с половиной минуты на тёплом Gradle, до десяти на
холодном. Сборка и текст столько не стоят, поэтому это отдельное решение.

**Не прикладывай**, если верно хоть одно:

- позвали «без среза», «быстро», «только сборку» — или скилл вызван с аргументом
  `без среза`;
- собранное приложение не демка platsdk. Для mymts кадров не прикладывай никогда:
  матрица рисует экраны SDK под Robolectric на мок-данных, и на телефоне
  тестировщик увидит другое. Картинка рядом со сборкой читается как «должно
  выглядеть так» и породит ложные баги;
- прогон матрицы упал.

Пропустил — **скажи об этом строкой в отчёте** и назови причину. Отчёт без раздела
про экраны читается как «интерфейс не менялся», а это другое утверждение. Заодно
это подсказка тебе же: захочешь срез — позовёшь ещё раз без аргумента.

Ничего из этого не мешает перечислить затронутые экраны текстом: текст берётся из
git и матрицы не требует.

Во всех остальных случаях — прикладывай.

```
cache=$(platsdk-baseline "$base")
zip="/tmp/srez-<ветка>-<ДД.ММ>.zip"
./gradlew :presentation:ui:testDebugUnitTest --tests 'ru.mts.platsdk.ui.screenshot.*' \
  && gallery-diff "$cache" presentation/ui/build/screenshots --zip "$zip"
```

Архив появляется, только если есть что в него класть. Путь к архиву бери из поля `zip` выходного JSON, а не из своей переменной
`$zip`: при нуле расхождений поля не будет, и отправлять нечего. Переменная же
останется заполненной в любом случае, включая падение матрицы. Слать файл,
не убедившись, что он создан этим прогоном, нельзя: по этому пути мог лежать срез
прошлой ветки.

```
apk-send file <путь из поля zip> "Срез галереи · <ветка> · изменившиеся экраны"
```

Отдельных картинок в ленту не шли ни в каком случае. Затронутые экраны
перечисляй текстом.

## Три раздела отчёта

**Что изменилось.** Экранами и поведением. «На экране оплаты мобильного при
ошибке загрузки теперь показывается модальное окно вместо пустого экрана».

**Как проверить.** Шагами, которые человек может повторить. Каждый шаг должен
опираться на изменение из диффа: не подтверждено git — в отчёт не идёт.

**Чего в этой сборке проверить нельзя.** Рефакторинг, изменения контрактов,
правки тестов, всё, что наружу через интерфейс не выходит. Раздел обязателен.
Без него у отчёта два плохих исхода: либо часть работы молча выпадает и отчёт
неполон, либо ненаблюдаемое выдаётся за проверяемое и человек ищет то, чего нет.

Сюда же — приоритетная ручная проверка по дельте находок из `gallery-diff`:
новая находка означает, что автопроверка увидела срезанный текст или пропавший
элемент, и это стоит посмотреть глазами в первую очередь. Формулируй результат,
а не механизм: «на узких экранах при крупном шрифте текст может не помещаться —
посмотрите экран X».

Сюда же — экраны, тронутые в коде, но не покрытые матрицей. Список непокрытых
вычитай из теста, наизусть не помни:

```
test=presentation/ui/src/test/java/ru/mts/platsdk/ui/screenshot/MatrixCoverageTest.kt
[ -f "$test" ] || echo "МАТРИЦЫ В ЭТОМ РЕПОЗИТОРИИ НЕТ"
sed -n '/val excused/,/^    )/p' "$test" 2>/dev/null | grep -oE '[A-Za-z0-9]+Screen::class' | sed 's/::class//'
git diff --name-only "$base" -- 'presentation/ui/src/main/*' 'presentation/ui-model/src/main/*'
```

Первая команда даёт список непокрытых экранов, вторая — изменённые файлы
интерфейса. **Сопоставь их сам**, автоматического способа нет: имя экрана из
списка встречается в `PlatSdkScreen.kt`, а вёрстка того же экрана живёт в файлах
с другими именами, так что ни грепом по диффу, ни грепом по путям это не решается.

Три правила, чтобы не соврать:

- вывод пуст или напечатано `МАТРИЦЫ В ЭТОМ РЕПОЗИТОРИИ НЕТ` — раздел пропусти и
  скажи об этом прямо. Молча написать «непокрытых экранов не тронуто» нельзя: это
  утверждение, для которого у тебя нет данных;
- диапазон здесь `"$base"` без `..HEAD`, чтобы в дифф попало и незакоммиченное;
- в чём не уверен, помечай как неуверенное. «Возможно, затронут» — честный ответ,
  «не затронут» без проверки — нет.

## Отправка

```
apk-send file qa-<репозиторий>-<ветка>-<ДД.ММ>.md "QA · <приложение> · <ветка>
<две-три строки сути>"
```
Имя файла обязано нести линзу, репозиторий и ветку: в «Избранном» отчёты со всех
веток лежат вперемешку, и три `отчёт.md` подряд неразличимы. Формат —
`<линза>-<репозиторий>-<ветка без feature/|bugfix/>-<ДД.ММ>.md`, например
`qa-platsdk-fatal-modal-10.09.md`. Косые черты в имени ветки заменяй дефисом.


Подпись длиннее 1000 символов обрезается, поэтому полный текст всегда файлом.
