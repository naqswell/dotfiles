# Ревью изменений

Сначала зафиксируй область: для незакоммиченной работы прочитай `git diff`,
`git diff --cached` и новые файлы из `git status --short`; для ветки используй
`git diff <base>...HEAD`. Не подменяй локальное ревью diff только до HEAD.

Прочитай применимые AGENTS.md, запрос и затронутый код. Выбери нужные критерии:

- [Ошибки кода](references/code-reviewer.md)
- [Тесты](references/pr-test-analyzer.md)
- [Скрытые ошибки и fallback](references/silent-failure-hunter.md)
- [Типы](references/type-design-analyzer.md)
- [Комментарии](references/comment-analyzer.md)
- [Упрощение](references/code-simplifier.md)

Это перенесённые критерии PR Review Toolkit. Ссылки на CLAUDE.md трактуй как
проектные AGENTS.md; model/Task/Agent в оригиналах не задают модель или клиент.
Проводи проверки последовательно либо через доступных подагентов, когда
делегирование предусмотрено запросом. Передавай им выбранный diff, правила,
ограничения и требование только читать. Не изменяй код в ходе ревью без запроса.

Проверяй каждую находку по коду. Сообщай только подтверждённые проблемы с
файлом, строкой, конкретным последствием и уровнем серьёзности. Если ошибок
нет, скажи об этом и назови существенные непроверенные условия. Не коммить
в режиме ревью и никогда не выполняй push.
