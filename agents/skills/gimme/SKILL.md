# Передача файлов между машинами: gimme

`gimme` отдаёт файл другой машине и показывает его там в Finder. Направление
определяется само по машине — указывать его не нужно и нельзя.

**Звать только по явной просьбе:** «скинь», «покажи», «дай посмотреть», «открой»,
«кинь». Сам, без просьбы, ничего не отправляй — иначе `~/inbox` зарастает, а у
человека посреди работы всплывает Finder.

```
gimme <путь>            отдать файл или папку другой стороне (и показать там)
gimme -n <имя>          принять со stdin:  ... | gimme -n отчёт.md
gimme --list            что человек положил в свой inbox
gimme --pull --latest   забрать оттуда самое свежее  («глянь, что я кинул»)
gimme --pull <имя>      забрать конкретное
```

Забрать можно только **файл**: папку `--pull` не умеет, а `--latest` папки
пропускает. Ненулевой код возврата означает, что ничего не доехало, — проверяй его.

Путь назначения печатается **последней строкой stdout** — бери его оттуда, не
парся остальное. Всё прочее, включая список непропущенных файлов, идёт в stderr.

Чего `gimme` не делает:

- **Не возит секреты.** Ключи, сертификаты, `keystore` и всё, что начинается
  с точки (`.env`), отсеиваются — и на отправке, и на приёме. Внутри папки такие
  файлы пропускаются, а их список печатается в stderr: это **не ошибка**, папка
  доехала, продолжай работу. Но если белый список выбросил из папки **всё**,
  `gimme` откажет целиком и вернёт ненулевой код — пустую папку он не отправляет.
- **Не читает диск другой машины.** Доступен ровно `~/inbox`, ничего больше.
  Просьбу «возьми файл с моего рабочего стола» выполнить нельзя — попроси
  положить файл в `~/inbox`.
- **Не чинит связь.** Если канал лёг, `gimme` печатает диагноз и, когда это
  применимо, команду, которая лечит. Передай их человеку дословно и не пытайся
  обходить канал вручную через `scp` или `ssh` — доступа туда нет.

Текстовый файл, который лежит в рабочем каталоге на этой же машине, показывать
через `gimme` не нужно: `orca file open <путь>` откроет его в редакторе Orca
на MacBook, ничего не копируя.
